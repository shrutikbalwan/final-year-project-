# Local Phase 1 backend API

The FastAPI application is in `backend/app/`. It accepts and returns the shared
Pydantic contract models from `contracts/v1/`. OpenAPI is generated by FastAPI;
Swagger UI is at `/docs` and the machine-readable document is `/openapi.json`.

## Start on Windows PowerShell

From the repository root:

First configure `HELMET_AUTH_SECRET` and `HELMET_BOOTSTRAP_USERS` in the same
PowerShell session using the [authentication setup guide](authentication-and-authorization.md).
There is no default user or signing key.

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip install -r requirements-dev.txt
$env:HELMET_DB_PATH = ".\data\smart_safety_helmet.sqlite3"
python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

The database file is created on first start and persists between restarts. The
`data/` directory and SQLite files are ignored by Git. Omit `HELMET_DB_PATH` to
use the same default path.

## Routes

| Method and path | Purpose |
| --- | --- |
| `GET /health` | Check API and local database readiness |
| `POST /api/v1/auth/login` | Exchange bootstrap credentials for a signed, expiring bearer token |
| `POST /api/v1/telemetry` | Validate and persist a shared `DeviceTelemetry` payload |
| `GET /api/v1/telemetry` | Paginated telemetry history with optional device and UTC time filters |
| `POST /api/v1/events` | Validate and persist a shared `SafetyEvent` for local vision events |
| `GET /api/v1/events` | Paginated detection event history with optional device and UTC time filters |
| `POST /api/v1/analytics/events` | Validate and persist a separate experimental ML `AnalyticsEvent` |
| `GET /api/v1/analytics/events` | Paginated list of stored analytics events |
| `GET /api/v1/helmets` | Paginated latest snapshot per device (`limit` 1 to 500, `offset` >= 0) |
| `GET /api/v1/helmets/{helmet_id}` | Retrieve the helmet summary and full latest telemetry |
| `GET /api/v1/helmets/{helmet_id}/risk` | Evaluate latest telemetry against the active workplace profile |
| `GET /api/v1/workplaces/profiles` | List active validated workplace profiles and rules |
| `PUT /api/v1/workplaces/profiles/{workplace_id}` | Administrator-only validated profile replacement (in-memory until restart) |
| `GET /api/v1/incidents` | Paginated incident records (`limit` 1 to 500, `offset` >= 0) |
| `GET /api/v1/incidents/{incident_id}` | Retrieve one stored incident |
| `GET /api/v1/incidents/{incident_id}/history` | Retrieve ordered incident history |
| `POST /api/v1/incidents/{incident_id}/acknowledge` | Acknowledge an open incident |

`helmet_id` is the contract's `device_id`. Telemetry and events return `201 Created`;
invalid contract payloads return `422`, duplicate telemetry or safety-event `event_id` returns
`409`, missing helmet/incident IDs return `404`, and storage failures return a
generic `500` (or `503` from the readiness check). List responses include
`items`, `limit`, `offset`, and `total`.

Telemetry and safety-event history accept optional `device_id`, `start`, and
`end` query filters; time filters must be UTC. `/helmets/{helmet_id}/risk`
evaluates the latest stored telemetry using the active profile and returns
`Unknown` when the profile is unavailable. Workplace profiles are exposed
read-only. The API permits browser requests from the local Vite development
origins `localhost:5173` and `127.0.0.1:5173`.

Analytics events use their own schema and storage table. Repeated analytics event
IDs return `409`; invalid payloads return `422`. These events do not create or
acknowledge safety incidents. See [ML analytics status](testing/ml-evaluation-readiness.md).

Incidents are generated by the route-independent rule-based safety engine when
telemetry is accepted. See [rule-based-safety-engine.md](rule-based-safety-engine.md)
for profile setup, score behavior, data-quality handling, acknowledgement, and
escalation. `POST /api/v1/events` stores the contract event and does not itself
create an incident. All data routes require bearer authentication and
server-side role checks. Configure local accounts using
[authentication and authorization](authentication-and-authorization.md).
`/health`, login, and API documentation are public. Keep this local API bound
to `127.0.0.1`; local authentication is not production identity management.

## Storage boundary

`backend/app/storage/interface.py` defines the persistence protocol used by the
service layer. `SQLiteStorage` is the local development adapter. A future
DynamoDB adapter can implement the same protocol; this project does not currently
connect to AWS or require AWS credentials.

## Checks

```powershell
python -m pytest -q
python -m pip check
```

Sign in at `POST /api/v1/auth/login` and send `Authorization: Bearer
<access_token>` on protected requests. Only administrators can replace a
validated workplace profile; supervisors and administrators can acknowledge
incidents.
